# 末日回声 · ECHO OF DOOMSDAY

一个使用 **标准 C++20** 编写的多分支末日生存文字游戏。剧情完全**数据驱动**，
拥有 **175 个互相关联的场景节点**（含 33 个死亡回溯点）、**15 条三档线索**、
**20 件关联道具**与 **11 个结局**（含真结局与完美真结局）。
全部剧情**逐字显示（slowprint）**。

> **版本 v1.0.3** —— 在 v1.0.2（存档 / 读档、已完成分支）基础上，菜单改为
> **↑ ↓ ← → 方向键 + 回车**控制（数字键与 L/S/R/Q 特殊键全部保留），
> 直接通过 termios 配置当前终端，**不创建 / 不依赖任何伪终端（pty）**。
>
> **历史**：
> v1.0.2 新增游戏内存档 / 读档（3 槽位）与已完成分支查看；
> v1.0.1 在 v1.0.0（3 结局 / 9 线索）基础上，新增 8 个区域、8 个结局、
> 6 条线索与 8 件道具，并补全世界观与人物群像。

## 一、故事背景

"灰雾日"后第 7 天，城市因一种诡异瘟疫沦陷。你在地铁应急避难所醒来，
发现自己拥有**时间回溯**能力：每次死亡，意识都回到避难所醒来的瞬间——
世界重置、伤痕消失，唯有**记忆与线索保留**。

你一次次走进灰雾，把用命换来的信息拼成真相。你会遇见在循环里反复广播的
电台主播、守着旧地图的退伍老兵、在小学里画壁画的女孩、守着防空洞的叛逃科学家……
最终你会发现：**困住这座城市的，是两代人、一场迟到了 30 年的告别。**

## 二、核心特性

- **逐字显示 slowprint**：字符逐个输出，逗号/句号/省略号自动停顿；
  播放期间按任意键可立即快进，提前输入的数字不会丢失。
- **多分支选择**：175 个场景、每个场景 2~7 个选项，错误选择会导致死亡。
- **方向键菜单（v1.0.3）**：所有菜单用 **↑ ↓（或 ← →）移动高亮、回车确认**，
  当前项反色高亮、首尾循环；同时保留数字键 1~N 直接选择。仅通过 termios
  把当前终端切到非规范模式读取按键，**不创建 / 不依赖伪终端（pty）**，
  菜单结束自动恢复终端设置（Windows 用原生 `conio`，方向键即开即用）。
- **死亡回溯机制**：死亡不是 Game Over，而是回到锚点、保留全部线索，
  可反复探索不同分支。
- **三档线索系统（共 15 条）**：
  - 基础线索（5 条）：描述"发生了什么"（现象层）；
  - 进阶线索（5 条）：揭示"谁在做、为什么"（阴谋层）；
  - 高级线索（5 条）：触及"末日的本质"（真相层）。
- **关联道具网络**：20 件道具（撬棍 / 门禁卡 / 防护服 / 手枪 / 电子管 /
  密码本 / 旧军事地图 / 炸药 / 抗体试剂……）跨区域解锁，把所有分支串成一张网。
- **11 个结局**：3 个原有结局 + 7 个扩展结局 + 1 个完美真结局。
- **存档 / 读档（v1.0.2）**：游戏内随时按 `S` 打开存档菜单，提供 **3 个槽位**；
  存档为纯文本（`doomsday_save1.dat` …），记录当前场景、回溯次数、线索、
  已访问场景与已达成结局，带魔数校验，损坏存档不会污染当前游戏。
- **已完成分支查看（v1.0.2）**：按 `R` 查看**场景探索进度（X/175）**与
  **结局收集进度（X/11）**，并列出全部结局（已达成显示标题、未达成显示 ？？？）；
  探索足迹跨死亡回溯保留。
- **高可拓展性**：剧情与逻辑彻底分离，新增内容几乎只改 `StoryData.cpp`；
  附带菜单式剧情编辑器 `add_story.py`，可自动加线索 / 场景 / 结局并重新编译。
- 完整支持中文（UTF-8），跨平台（Linux / macOS / Windows / Termux）。

## 三、目录结构

```
echo-of-doomsday/
├── include/
│   ├── GameTypes.h    # 数据结构：Clue / Choice / Scene / Ending（聚合体）
│   ├── Terminal.h     # 终端接口：slowprint、颜色、菜单读取
│   ├── StoryData.h    # 剧情数据库只读接口
│   └── GameEngine.h   # 游戏引擎接口
├── src/
│   ├── Terminal.cpp   # 终端实现（逐字输出 / 跨平台键盘检测 / UTF-8）
│   ├── StoryData.cpp  # ★ 全部剧情数据（拓展时主要改这里；分卷见下）
│   ├── GameEngine.cpp # 引擎实现（场景流转 / 线索 / 结局 / 回溯 / 存档 / 进度）
│   └── main.cpp       # 程序入口
├── add_story.py       # 菜单式剧情编辑器（加内容后自动编译）
├── Makefile
├── LICENSE            # MIT 许可证
└── README.md
```

> **StoryData 分卷**：为方便网盘上传，剧情数据按 9 个分卷提供
> （`StoryData.part01.cpp` … `StoryData.part09.cpp`），编译前需先拼接：
> ```bash
> cd src && cat StoryData.part*.cpp > StoryData.cpp && cd ..
> ```
>
> **运行时生成的存档**（已加入 `.gitignore`，不随源码分发）：
> `doomsday_save1.dat` / `doomsday_save2.dat` / `doomsday_save3.dat`。

## 四、编译与运行

需要支持 C++20 的编译器（GCC 11+ / Clang 13+ / MSVC 2021+）。

```bash
make          # 编译生成 ./doomsday
make run      # 编译并运行
make clean    # 清理
```

或手动编译：

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Iinclude \
    src/main.cpp src/Terminal.cpp src/StoryData.cpp src/GameEngine.cpp -o doomsday
./doomsday
```

> **Termux（Android）**：用 `clang++` 替换 `g++`。注意网盘下载目录在
> 共享存储（`~/storage/downloads/...`，挂载为 noexec，**无法直接执行**），
> 需先复制到家目录、拼接分卷再编译运行：
> ```bash
> cp -r ~/storage/downloads/BaiduNetdisk/endingday-plan-1.0.3 ~/
> cd ~/endingday-plan-1.0.3
> (cd src && cat StoryData.part*.cpp > StoryData.cpp)
> clang++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Iinclude \
>     src/main.cpp src/Terminal.cpp src/StoryData.cpp src/GameEngine.cpp -o doomsday
> ./doomsday
> ```

**操作**：

| 按键 | 功能 |
|---|---|
| `↑` `↓`（或 `←` `→`） | 移动高亮选项（首尾循环） |
| 回车 | 确认当前高亮项 |
| 数字 `1`~`N` | 直接选择对应项（旧习惯保留） |
| `L` | 随时查看线索本（含未获得线索的占位与进度） |
| `S` | 打开**存档 / 读档菜单**（3 个槽位） |
| `R` | 查看**已完成分支**（场景探索 + 结局收集进度） |
| `Q` | 退出游戏 |

> 方向键在终端中是 ANSI 转义序列（`ESC [ A/B/C/D`），需要终端进入
> 非规范模式逐个读取；本游戏仅临时修改当前终端的 termios 设置，菜单结束
> 立即恢复，不创建任何伪终端。

## 七、拓展教程（高可拓展性）

### 1. 新增一条线索

在 `src/StoryData.cpp` 的 `kClues` 表中追加：

```cpp
Clue{
    .id = "B6",                       // 唯一编号
    .tier = ClueTier::Basic,          // 所属阶段（或 Item 道具）
    .name = "线索名称",
    .detail = "在线索本中展示的详细描述。"
},
```

### 2. 新增一个场景 / 分支

```cpp
Scene{
    .id = "new_place",
    .title = "新地点",
    .paragraphs = { "第一段文字。", "第二段文字。" },
    .choices =
    {
        Choice{ .text = "继续前进", .target = "next_scene" },
        Choice{ .text = "拾取物品", .target = "new_place", .grantedClue = "B6" },
        // 一次授予多个（v1.0.1 起）
        Choice{ .text = "同时拿走两样", .target = "back",
                .grantedClues = { "tool_a", "tool_b" } },
        // 条件选项
        Choice{ .text = "需要前提的行动", .target = "xxx",
                .requireAll = { "A2" }, .requireNone = { "B6" } },
        // 直接触发结局
        Choice{ .text = "做出最终决定", .target = "", .endingId = "ending_x" },
        Choice{ .text = "回到避难所", .target = "hub" },
    },
},
```

### 3. 新增一个结局

在 `kEndings` 表中追加，并让某个选项的 `endingId` 指向它：

```cpp
Ending{
    .id = "ending_x",
    .title = "结局 · 标题",
    .paragraphs = { "结局正文……", "【达成结局：标题】" },
},
```

### 4. 新增更复杂的条件

若需要"拥有任意一个""回溯次数达到 N"等条件，只需：
1. 在 `GameTypes.h` 的 `Choice` 中增加字段（聚合体可带默认值）；
2. 在 `GameEngine::isChoiceAvailable()` 中增加对应判断。

剧情数据的写法、其余引擎逻辑均无需改动。

### 5. 存档文件格式（v1.0.2）

存档为纯文本 `key=value`，首行魔数 `# ECHO_SAVE`，可直接用文本编辑器查看：

```text
# ECHO_SAVE
version=1
loop=12                 # 回溯次数
scene=hub               # 读档后出现的场景 id
clue=B1                 # 已拥有线索（可多行）
clue=A2
visited=market_outside  # 已访问场景（可多行）
ending=ending_basic     # 已达成结局（可多行）
```

读档时先读入临时变量，**校验魔数与场景存在后才一次性覆盖**当前状态，
因此存档损坏或被截断都不会破坏正在进行的游戏。所有 id 仅含字母 / 数字 /
下划线，不含 `=`，解析安全。

## 八、用到的 C++20 特性

- **指定初始化器（designated initializers）**：让剧情数据字段自解释；
- **`std::string_view`**：字符串零拷贝传递；
- **`constexpr`**：颜色常量等编译期求值；
- **聚合体默认成员初始化器**：未指定字段安全兜底，配合 `-Wextra` 零警告；
- 现代标准库（`std::find_if` / `std::count_if` 等）。
